FLUJO DE DATOS EJEMPLO:

Usuario interactúa con UI
    ↓
Dumb Component emite @output() evento
    ↓
Smart Container (inyecta Use Case)
    ↓
Use Case ejecuta lógica de negocio
    ↓
Use Case inyecta Repository (puerto)
    ↓
    ├─→ EN TEST: Mock Repository
    └─→ EN PROD: HttpAdapter (implementación real)
    ↓
Repository hace operación (HTTP, BD, etc.)
    ↓
Respuesta actualiza Signals en Use Case
    ↓
Template reactivo con signal() se actualiza
    ↓
Usuario ve resultado

VENTAJAS DE ESTA ARQUITECTURA:

✅ VERTICAL SLICING
   • Cada slice es independiente
   • Puedes eliminar un slice sin romper la app
   • Facilita trabajo en paralelo de equipos

✅ ARQUITECTURA HEXAGONAL
   • Domain sin dependencias (testeable)
   • Adaptadores intercambiables (HTTP, WebSocket, etc.)
   • Lógica desacoplada del framework

✅ SCREAMING ARCHITECTURE
   • Nombres que explican qué hace el sistema
   • join-waitlist.use-case.ts = Registrarse en lista
   • Sin necesidad de leer código para entender

✅ ANGULAR 21 SIGNALS
   • Reactividad moderna y performante
   • Sin RxJS innecesario
   • Sintaxis limpia

✅ COMPONENTES STANDALONE
   • Sin módulos
   • Composición directa
   • Inyección granular

═════════════════════════════════════════════════════════════════════════════

PATRONES IMPLEMENTADOS:

🏗️  Repository Pattern
   domain/waitlist.repository.ts → infrastructure/http-waitlist.adapter.ts

🔄 Use Case Pattern
   application/join-waitlist.use-case.ts → Orquesta la lógica

🔌 Adapter Pattern
   Múltiples adaptadores pueden implementar el mismo puerto

♻️  Dependency Injection
   Angular provee automáticamente las dependencias

📊 Data Model Isolation
   Domain models no conocen Angular, HTTP ni UI
